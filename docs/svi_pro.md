# Stable Video Infinity 2.0 Pro

`SESVIProVideo` is a clip controller using ComfyUI's native Wan models, samplers,
LoRA patchers and VAE. It does not replace or modify TeaCache/H3 nodes or ComfyUI
core. Requires current ComfyUI with native `VIDEO` support; no new Python package
is required in the SECourses bundle.

## Use

- Load the matching high/low Wan 2.2 **I2V 14B** models, UMT5 and Wan **2.1** VAE.
- Supply a starting image. Put one prompt per paragraph in `prompts`; blank lines
  advance to the next clip's prompt. The final paragraph repeats.
- `clip_count` controls duration. With 81 frames and one motion latent, the first
  clip contributes 81 frames and subsequent clips 76. Three clips at 16 FPS last
  14.5625 seconds. Each clip uses `seed + clip index`.
- Quality preset: 30 steps, CFG 4, Euler/simple, shift 5, switch sigma 0.875.
- Optional `fast_mode` applies the selected Seko high/low acceleration pair.
  Set 4 steps / CFG 1 as well. This is a bundle-compatible speed variant, not the
  official quality recipe; identity, motion and prompt adherence can differ.
- `motion_latent_count=1` is the Pro recipe. Zero disables motion carry. Counts
  are limited to leave space for new frames. `tiled_vae` reduces decode VRAM.
- `continue_video` extends `source_video`; `append_source` includes the original
  at the requested FPS/resolution. Without a separate image, its first frame is
  the identity anchor. Input audio is not copied; output is silent H.264 MP4.
- For exact resume in ComfyUI, save `last_clip_latent`, connect it to
  `previous_latent` next time, keep the same anchor/resolution and advance the
  seed. Without it, source-video continuation re-encodes the last context frames.
- Native model-only LoRA loaders before the model inputs allow compatible style
  adapters. Alternative high/low **I2V** pairs are selectable; quality is not
  guaranteed for distilled/merged variants.

## Existing bundle files

No automatic downloading is implemented. The presets use:

- `wan2.2_i2v_{high,low}_noise_14B_fp8_scaled.safetensors`
- `umt5_xxl_fp8_e4m3fn_scaled.safetensors`
- `Wan/wan_2.1_vae.safetensors`
- `SVI_Wan2.2-I2V-A14B_{high,low}_noise_lora_v2.0_pro.safetensors`
- Optional `Wan2_2-I2V-A14B-4steps-lora-rank64-Seko-V1_{High,Low}.safetensors`

Official SVI files have unprefixed PEFT `blocks.*.lora_A/B.default.weight` keys.
The controller translates these in memory to native ComfyUI names before loading.
Ordinary native LoRA loading does not recognize those original keys. Files on
disk are never converted or overwritten.

## Method and scope

Based on [SVI 2.0 Pro](https://github.com/vita-epfl/Stable-Video-Infinity/tree/svi_wan22)
and the conditioning contract exposed by Kijai's `WanImageToVideoSVIPro`:
fixed first-frame anchor, previous **clean latents**, Wan-normalized zero padding,
anchor-only conditioning mask, and removal of the repeated anchor/motion prefix.
High/low models switch at the actual sigma boundary. Only one decoded clip is
held in memory and output is encoded incrementally.

This is inference support, not training. SVI-Talk, SVI-Dance and EverAnimate use
separate models and are not Pro switches. Text-only generation first needs an
image generated by a separate image model. There is no arbitrary ending-frame,
audio-driven lip-sync or pose-control feature in this Pro implementation.

Run `python tests/test_svi_pro.py` with the ComfyUI venv for CPU checks of
conditioning, LoRA key conversion, non-mutation, prompt scheduling, per-clip
seeds, prefix trimming, source continuation, exact resume and MP4 timestamps.
